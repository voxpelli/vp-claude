- **PostToolUseFailure shows misleading "hook stopped continuation" label** (2026-03-28) \[cosmetic\] — When a PostToolUseFailure prompt hook fires, the Claude Code framework wraps the output with a "hook stopped continuation" label in the TUI. This is misleading — the hook didn't stop anything, the tool itself failed before the hook ran. Cannot fix from plugin side. Tracked: claude-code#27886, #18427, #17088.

- **Embedded `grep`→`ugrep` shim amplifies regex memory** (2026-07-01) \[degraded\] — Claude Code's Bash-tool `grep` shim resolves to `exec -a ugrep "$CLAUDE_CODE_EXECPATH" ...` — i.e. `grep` calls run inside the full `claude` binary, not a lean standalone `ugrep`. The binary is a **Bun v1.4.0 / JavaScriptCore** build (verified directly via `strings`/`otool` — Mach-O sections `__jsc_int`/`__jsc_opcodes`/`__bun`; no V8), and it embeds what appears to be the real Genivia `ugrep 7.5.0`/RE-flex engine (a genuine `ugrep 7.5.0` version banner + Genivia/RE-flex attribution text are present in the binary) rather than a from-scratch JS reimplementation — so the upstream issue's "V8-heap" and "catastrophic backtracking" framing (RE-flex is DFA-based, not a classic backtracking engine) are both likely imprecise, though the exact allocation path wasn't pinned down further (no disassembly). Piping `strings -a` over the 227 MB `claude` binary itself (which embeds a ~467,000-character single-line minified JS blob) into `grep -o '.{0,80}X.{0,120}'` ballooned this wrapper to a **14 GB** phys_footprint peak, independently caught by a sibling local memory-monitoring toolkit, before self-terminating. Reported (not independently verified) comparison: ~754 MB for a real standalone `ugrep` and ~2.8 MB for real `/usr/bin/grep` on an equivalent repro. Independently reproduced by others on macOS, WSL2, and bare-metal Linux through at least v2.1.183. \[upstream: [anthropics/claude-code#54394](https://github.com/anthropics/claude-code/issues/54394)\]
  Severity: degraded · Ownership: upstream · Workaround: partial — use `command grep` or an explicit path (`/usr/bin/grep`), or `rg`, to bypass the shim; fold long lines (`fold -w 2000`) before matching when scanning binaries with large embedded string blobs.

- **Bash-tool timeout doesn't kill the full child process group — detached children keep running** (2026-07-01) \[degraded\] — A subagent's Bash-tool call (a multi-command `strings | grep` shell block) returned/timed out, but its spawned shell and pipeline children kept running **detached** for roughly 13 more minutes — invisible to any PID-tree-based orphan/leak detector, since the parent shell was never reparented to PID 1; the process tree stayed fully intact, only the _logical_ owner (the tool call itself) had ended. Distinct root cause from the PID-1-reparenting orphan cluster (#1935/#27707/#33947, tracked separately in a sibling toolkit's roadmap) — this is about process-group kill on timeout, not reparenting. \[upstream: [anthropics/claude-code#68647](https://github.com/anthropics/claude-code/issues/68647)\]
  Severity: degraded · Ownership: upstream · Workaround: none — no user-facing way to detect or terminate a detached tool-call child from within Claude Code; it relies on the command finishing or exhausting on its own.

- **Sub-agent `permissions.allow` doesn't inherit from user-level `~/.claude/settings.json`** (2026-05-18) \[degraded\] — Sub-agents launched via the `Agent`/Task tool inherit only project-scope permissions (`.claude/settings.local.json`), not user-scope (`~/.claude/settings.json`): Bash patterns or `mcp__*` tool names pre-allowed at user scope are silently denied inside a sub-agent even though the main thread (which sees both scopes) succeeds. Directly bites this plugin's read-only agents (`knowledge-gardener`, `knowledge-maintainer`, `knowledge-primer`, `raindrop-gardener`), which run heavy `mcp__basic-memory__*` + Bash workloads as sub-agents. Not a sandbox issue (the OS sandbox is opt-in; `/tmp/` writes work in sub-agents) — the blocker is `permissions.allow` scope inheritance. Related: `#51057` — `/fewer-permission-prompts` silently drops env-var-prefixed commands (`FOO=bar npm test`), so a generated rule can still miss sub-agent patterns (closed NOT_PLANNED 2026-05-26 — won't be fixed, so the caveat is permanent). \[upstream: [anthropics/claude-code#18950](https://github.com/anthropics/claude-code/issues/18950)\]
  Severity: degraded · Ownership: upstream · Workaround: full — run `/fewer-permission-prompts` for a baseline, then hand-curate `.claude/settings.local.json` for anticipated sub-agent operations.
